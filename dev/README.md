# Local test environment

Two out-of-the-box Stash containers for developing and testing the plugin, plus synthetic test media.
Needs Docker (Docker Desktop on macOS/Windows). All commands run from this `dev/` folder.

| Instance | Image | URL |
|---|---|---|
| `stash-v0311` | `stashapp/stash:v0.31.1` (oldest supported) | http://127.0.0.1:9931 |
| `stash-dev` | `stashapp/stash:development` | http://127.0.0.1:9932 |

Stash's databases, generated files and the test media live in Docker volumes, never in the repo folder
(SQLite must not sit on a network share). The plugin is mounted read-only into both instances from a copy on
this computer's own disk (`~/.imaglr-dev/plugin`, or `$IMAGLR_DEV_PLUGIN`), with its `data/` subfolder overlaid
by a per-instance volume. After a code change run **`npm run dev`** (build + copy), then
**Settings → Plugins → Reload plugins** in Stash. (Mounting the repo folder directly is unreliable when the repo
is on a network share: Docker's view of rebuilt files goes stale.)

## First run

```sh
(cd .. && npm ci && npm run dev)               # install build tooling (Node 22.18+), build the plugin, copy it to ~/.imaglr-dev/plugin
mkdir -p ~/.imaglr-dev/plugin/data             # mount point for the plugin data volume
docker compose run --rm make-media             # synthetic test media (≈25 MB)
docker compose up -d
python3 seed.py 9931 setup                     # first-run setup, scan, generate, sample metadata
python3 seed.py 9932 setup
```

## Everyday use

```sh
docker compose up -d / docker compose stop     # start / stop both instances
python3 seed.py 9931 auth on                   # require login: dev / dev-password
python3 seed.py 9931 auth off                  # back to no login
python3 seed.py 9931 status                    # version, setup state, login on or off
docker compose logs -f stash-v0311             # Stash log, including plugin output
docker compose down -v                         # delete everything (volumes too) to start clean
```

## Test media

Generated by `make_media.py`: test patterns only, no real content.

- **Scenes (3):** H.264 1080p with title/comment/location tags and chapters to strip; vertical H.264;
  HEVC in MKV (not browser-playable).
- **Images (11):**
  - JPEG with EXIF orientation 6, GPS, camera model, XMP and a comment;
  - plain JPEG; PNG with alpha and metadata chunks; opaque PNG; still and animated WebP; animated GIF; AVIF;
  - three images inside `galleries/zipped_gallery.zip`.
- **Metadata** added by `seed.py`:
  - tags on every scene and image, including `AI_Housekeeping` (excluded by the default pattern) and a
    tag over 64 characters;
  - a performer and a studio;
  - one marker (5–12 s) per scene.
  - Workflow tags (`imaglr`, `imaglr-sent`) are deliberately **not** created: the plugin must do that.

## imaglr during testing

Everyday testing uses a **fake imaglr** (`fake_imaglr.py`, service `fake-imaglr`), which the test Stash instances
reach through the development-only `IMAGLR_API_BASE` environment variable. It implements only the five routes the
plugin may call and logs any other call as `UNEXPECTED ROUTE`. Received posts, with their files and kept tags,
are listed at http://127.0.0.1:8900/.

The key you add in the plugin picks the fake blog and scenario: `pbk_blogone|x` and `pbk_blogtwo|x` are working
blogs; `pbk_invalid|x`, `pbk_noscope|x`, `pbk_premium|x`, `pbk_suspended|x`, `pbk_ratelimit|x`, `pbk_flaky|x`,
`pbk_nopublish|x` and `pbk_rejected|x` produce imaglr's error cases (details in the file's docstring). Tags named
`banned` or `banned-…` are silently dropped, as imaglr does.

Real imaglr is only used at agreed checkpoints:

```sh
IMAGLR_API_BASE=https://imaglr.com/api/v2 docker compose up -d   # point the test Stash at real imaglr
docker compose up -d                                             # back to the fake
```

A real test blog's key belongs in `dev/.env.local` (git-ignored; nothing reads it automatically — paste it into the
plugin's Settings when testing against real imaglr). Never paste keys into commits, issues or chat.

## Running the tests

Prerequisites: Node 22.18 or newer, Python 3.9 or newer, and `npm ci` once. ffmpeg is optional (the real-media tests
skip without it) and Docker is optional (only for the container and end-to-end runs).

```sh
npm run typecheck           # TypeScript
npm test                    # UI unit tests (node:test, tests/js)
npm run test:py             # Python unit tests (tests/python)
npm run test:py:stash       # the same inside stashapp/stash:v0.31.1 (needs Docker; real ffmpeg)
python3 dev/e2e.py 9931     # end to end against the running test Stash + fake imaglr (after `seed.py 9931 setup`)
```

CI runs all of these on every push (the Python tests on Ubuntu and Windows), plus a privacy scan
(`scripts/check-generic.sh --all`). macOS isn't in CI; run `npm run test:py` there by hand before a release.

## Privacy gate (contributors)

The repository is published anonymously. Enable the git hooks once per clone so nothing personal can be committed:

```sh
git config core.hooksPath .githooks
```

`scripts/check-private.sh` then checks every commit's staged content and message against
`scripts/check-generic.sh` (private-network addresses, local paths, e-mail addresses, key shapes) and, for the
owner, a private pattern file outside the repo (`docs/private/private-patterns.txt`; contributors without it should
run `scripts/check-generic.sh` directly).

## Demo instance for screenshots and recordings

A third instance, `stash-demo` (http://127.0.0.1:9933), with public-domain, safe-for-work media and friendly
metadata, talking to the **real** imaglr (add demo blogs to it in the plugin's Settings). Its state lives in
its own Docker volumes; the media lives on this computer in `~/.imaglr-dev/demo-media` (credits in
`CREDITS.txt` there — Prelinger Archives films from archive.org and NASA images, all public domain).

```sh
python3 demo_media.py                          # fetch ≈220 MB of films and images (once)
docker compose up -d stash-demo
python3 seed.py 9933 demo                      # first-run setup, scan, tags/studios/markers, no release-notes popup
```

Recording tips: use a clean browser profile at `http://localhost:9933` (never a LAN address), crop to the page,
and keep blog names generic — every frame goes into the public repository.
